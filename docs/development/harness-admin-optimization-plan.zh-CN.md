# 管理后台 Harness 优化执行计划

## 1. 目标与范围

- 计划日期：2026-11-06。
- 对象：管理后台 Claude Code / Codex 的模型选择、资格解释、发布状态和接入体验。
- 本文保留执行方案并记录实施验收结果。P0–P5 和 G1/G2 已完成；X1 未实施，详见末节。
- 不包含测试基础设施 `test/lib/harness.js` 的优化。

目标是让管理员能够准确回答：模型为什么能或不能加入目录、当前修改是否生效、客户端如何接入，以及客户端最终会看到哪些元数据。

### 必须保留的约束

1. Claude Code 必须原生 Messages，Codex 必须原生 Responses；使用最终上游 URL 对应的协议判断，不能通过放宽资格或自动改路由解决问题。
2. 保持目录发布开关、成员选择和请求兼容策略相互独立。关闭目录保留成员；关闭后仍不能保存不符合资格的已选模型。
3. 配置预览不持久化、不调用真实上游。结构资格、目录发布和实际连通性是不同事实。
4. 保持客户端权限过滤、管理员认证、CSRF、自定义管理路径和密钥脱敏/恢复机制。
5. 编辑通过现有 `updateConfig` / 路径助手和统一审阅保存流程，不增加绕过全局保存的局部自动保存。
6. 保留隐藏字段、有效零值、环境管理值及 Profile 限制；两个 Profile 使用同一套实现。
7. 不新增基于模型名称、Catalog 猜测或提供商版本的请求拒绝规则；不修改 JSON/SSE 公共协议契约。

## 4. 分阶段任务与验收

### P0：先固化回归

**工作**

- 新增 `test/admin-harness-form.test.js`，复用 [admin-workspace-form](../../test/lib/admin-workspace-form.js)，不引入新测试框架。
- 把已复现行为改成断言正确结果的失败回归：刷新失败不得添加；模型变化不得借用其他模型的资格。
- 补充完整 App 的异步请求回归，覆盖组件 props 单测无法证明的请求竞争和跨页切换。
- 保留发布开关、成员移除、隐藏配置及后端拒绝非法已选模型的既有契约。

**验收**

- 修复前，两项核心回归因预期缺陷失败，而不是因测试环境错误失败。
- 当前后端原生路由、目录发现和静态预览契约保持通过。

### P1：修复资格结果可信度

**主要文件**：[App](../../admin-ui/src/App.jsx)、[HarnessTab](../../admin-ui/src/components/HarnessTab.jsx)、[api](../../admin-ui/src/api.js)。

**工作**

1. 统一资格结果有效性判定：请求成功、对应当前配置与 Catalog 上下文、未处于刷新或错误状态。
2. 以 `modelId` 关联资格；ID 为空、重复、改名、被删除或找不到对应资格时不可添加，不回退到数组下标。
3. 修改选择状态时，重新在当前配置中定位唯一模型，避免弹窗打开后数组变化写错对象。
4. 打开弹窗、选择候选、确认添加三个环节均检查资格；刷新/失败/候选失效时禁用确认。移除成员仍可操作，以便修复无效配置。
5. 保留请求序号和快照防护；给资格请求传递 `AbortSignal`，在切页、卸载或新请求替代时取消旧请求。取消不能取代响应新鲜度检查。
6. 加入显式重试及加载/失败提示。保留现有防抖，不提前引入结果缓存或复杂请求调度器。

**验收**

- 覆盖首载、延迟成功、失败、旧成功晚到、旧失败晚到、切页返回和 Catalog 更新。
- 配置重排、删除、改名后，不得显示其他模型的资格或修改其他模型。
- 弹窗打开期间资格失效，确认不能写配置；空选择不能隐式变成第一个模型。
- 连续编辑只允许最新结果生效；组件卸载后不更新状态；真实错误可见，预期取消不显示失败告警。

### P2：把“不可选”变成可解释、可修复

**主要文件**：[HarnessTab](../../admin-ui/src/components/HarnessTab.jsx)、[App](../../admin-ui/src/App.jsx)、[i18n](../../admin-ui/src/i18n.jsx)、[model-validation](../../src/model-validation.js)。

**工作**

- 添加弹窗展示全部模型，支持名称/ID/上游搜索，以及“可添加 / 已选择 / 不符合条件”筛选。
- 不符合条件的条目保持可读但不可选；展示全部阻断原因，而非只取第一条。
- 依据原因码映射中英双语说明；优先复用已有结构化字段，确有缺口时再以兼容方式补充参数，不解析英文错误文本。
- 未知原因码保留后端说明和代码，不伪造“符合条件”状态；刷新失败不显示为“没有模型符合条件”。
- 提供跳转对应模型、上游或公共路由设置的入口，保留当前未保存草稿，不自动修改路由。
- 区分无模型、全部已选、全部不符合条件、搜索无匹配和资格查询失败。

**验收**

- 模型/上游禁用、上游缺失、Catalog 未匹配、公共路由禁用、非原生协议、Codex 图片模型限制均有可理解说明。
- 同一模型多个原因全部可见；任一阻断原因存在时都不可添加。
- 导航进入正确实体且不丢草稿；被删除的目标提示失效，不跳到同下标的其他实体。
- 中英文、长模型名、键盘选择和移动端布局正常。

批量添加暂不作为本阶段必需项；先验证搜索与筛选足以支撑多模型管理，避免扩大选择一致性修复范围。

### P3：分开表达草稿、发布与验证事实

**主要文件**：[HarnessTab](../../admin-ui/src/components/HarnessTab.jsx)、[App](../../admin-ui/src/App.jsx)、[server](../../src/server.js)、[OpsTab](../../admin-ui/src/components/OpsTab.jsx)。

**工作**

1. 将“可用”改为“配置符合原生路由条件”，将未知资格与不符合条件分开。
2. 以当前草稿、现有已加载配置基线分别表达待添加、待移除和已保存成员。
3. 生效状态必须依据运行时有效配置，而非仅凭“已保存”。必要时给资格接口追加生效目录摘要，保留现有 `catalogs`、`items`、`capabilities` 字段。
4. 区分“目录发布已启用”和“某个客户端实际可见”：后者仍受调用者 API Key 权限过滤。静态摘要不宣称验证过客户端发现。
5. 保存成功才更新基线；保存失败保留草稿并显示错误；重载、环境覆盖和 Profile 限制均不误标生效。
6. 显示“未进行客户端连通性验证”，提供进入现有运维模型验证的入口，并说明该验证针对生效配置，不等价于 CLI、工具闭环或原生 SSE 完整验收。

**验收**

- 关闭目录后成员仍保留，显示未发布；开启目录但零成员时有明确空目录提示。
- 无效已选成员即使目录关闭也不能绕过后端保存校验。
- 草稿预览发出零上游请求、零配置写入；不能改变现有公开模型发现结果。
- 保存失败不显示成功状态；重新加载后展示与有效配置一致的目录摘要。
- 普通模型列表、Claude Code 列表和 Codex 列表仍保持原有权限与格式协商行为。

### P4：提供可复制的客户端接入向导

**主要文件**：[HarnessTab](../../admin-ui/src/components/HarnessTab.jsx)、[i18n](../../admin-ui/src/i18n.jsx)、[README](../../README.md)、[客户端接入说明](claude-code-codex-requirements.md)。

**工作**

- 生成 Claude Code 的代理根地址、认证变量和模型发现开关示例。
- 生成 Codex provider 配置，正确处理 `/v1`、`wire_api = "responses"`、`supports_websockets = false` 和已选公共模型 ID。
- 公共代理地址支持管理员确认/编辑；管理路径不能被拼入公共 API 地址，也不能仅根据浏览器管理地址断言公网入口。
- 使用凭据占位符；不读取已保存密钥、不把认证信息放入 URL、不写入客户端配置文件。
- 说明草稿配置尚未生效、目录开关/权限导致不可见和客户端目录刷新排查方法。
- 开始实现时核对仓库固定 CLI 版本和官方配置说明；新版本差异不直接扩展本计划的兼容承诺。

**验收**

- 根地址与已有 `/v1` 地址均不会生成重复路径；自定义管理路径不污染客户端地址。
- 生成片段正确转义地址与模型 ID，复制成功/失败均有明确反馈。
- 示例与文档一致且不含真实凭据；用户没有复制或执行时，不产生网络请求或外部文件变更。

### P5：Codex 元数据预览与高级编辑

**主要文件**：[server](../../src/server.js)、[model-validation](../../src/model-validation.js)、[HarnessTab](../../admin-ui/src/components/HarnessTab.jsx)、[i18n](../../admin-ui/src/i18n.jsx)。

**工作**

1. 先把现有 Codex 元数据解析/序列化提取为最小共享纯函数，显式传入相应 Catalog 快照，先冻结原有输出，再接入管理员预览。
2. 展示最终上下文窗口、推理档位/默认值、排序和基础指令，并标注配置覆盖、Catalog 或既有默认回退来源。
3. 草稿预览使用草稿快照；生效预览使用生效快照，不调用依赖全局生效状态的解析器来计算草稿。
4. 折叠高级区只编辑已经支持的 `models[].codex` 字段；支持清除覆盖恢复继承，保留其他未知/隐藏字段。
5. 沿用既有配置规则，明确上下文窗口正安全整数、优先级零值及推理默认值解析行为。发现既有非法组合处理差异时，先记录契约，不借本次 UI 工作悄悄收紧请求策略。
6. 不复制 Catalog 的价格/能力/推理定义，不在前端再实现一套回退规则。

**验收**

- 同一有效配置下，预览字段与真实 `/v1/models?format=codex` 输出一致；说明消费者权限仍会影响最终成员列表。
- 对配置覆盖、Catalog 值、既有回退、清除覆盖、显式零值分别断言原始配置和最终输出。
- 基础指令等字段保存、重载后不丢失；无编辑时不把解析后的默认值自动写入配置。
- 提取共享函数前后公开目录 JSON 不发生非预期变化。

### X1：可选的客户端原生路径自检

不纳入 G1/G2 的必需范围。只有明确需要在 Harness 内发起真实请求时，才启动单独设计与实施：

- 明确测试所用的生效模型、客户端身份、请求预算、超时和取消；不绕过权限边界，也不自动取用管理员保存的客户端密钥。
- 分别检验模型发现、原生 JSON、原生 SSE 终态和错误，不把普通模型探测的 HTTP 200 当成完整客户端兼容。
- 工具调用闭环、CLI 多轮和真实提供商能力另列验收项；结果记录配置/Catalog 身份和检测时间，相关配置变化后失效。
- 每次真实调用均由用户明确触发并提示可能计费；失败可见，不自动重试成成功结果。
