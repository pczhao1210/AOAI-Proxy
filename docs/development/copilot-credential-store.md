# Copilot credential store

`src/copilot-credentials.js` exports two async factories:

- `openFileCredentialStore({ directory })`: private local POSIX directory, **one writer**.
- `openPostgresCredentialStore({ pool, schema = "public", namespace = "default" })`: existing `pg.Pool`, shared by instances. Set the same namespace on replicas and **different namespaces for independent deployments** sharing a schema. The store does not close the pool.

Copilot-specific encryption has been removed at the owner's request. New active/prepared records use `{format: "plaintext-v1", ref, secrets}`. `COPILOT_CREDENTIAL_KEY_VERSION` and `COPILOT_CREDENTIAL_KEYS` are no longer read, and there is no startup-generated fallback key. The caller selects the directory/pool at startup. File permissions and database access restrictions protect the store; anyone with storage read access can read tokens, and there is no cryptographic at-rest integrity protection. Ordinary configuration is also unencrypted at the application layer. The [global encryption design](../../encrypt_design.md) is a future implementation, not an enabled feature.

Old `{ref, envelope}` ciphertext is detected but never decrypted or automatically deleted. Reads, admission, refresh and activation fail with `CREDENTIAL_LEGACY_ENCRYPTION_UNSUPPORTED` (admin/provider code: `COPILOT_LEGACY_ENCRYPTION_UNSUPPORTED`). Metadata-only identity lookup still supports same-principal reauthorization and explicit local revocation. A new candidate can replace an old active credential only after successful provider authorization, configuration publication and apply; the old record remains until then. An old prepared candidate must be explicitly discarded after checking saved/active/pending configuration ownership; another login cannot silently overwrite it. Keep protected backups; do not delete rows or sidecars to bypass conflicts.

Pass `binding = { channelId, principalId, profile }`, where `principalId` is the verified, immutable provider account identifier (not a display name), and `profile` is `vscode` or `opencode`. These are **server-derived** inputs. A channel cannot move to another principal/profile; create a new channel for that. Methods are async:

| Method | Contract |
|---|---|
| `status(binding)` | `{state, generation, credentialVersion, credentialRef, preparedRef, rotationPending}`. States: `empty` (initial generation 0), `prepared`, `active`, `revoked`. With an active credential, `credentialRef` always denotes the active reference, even while a separate candidate exists. Metadata only; not a usability check. |
| `prepare(binding, secrets, expectedGeneration)` | Durably prepare a bounded plaintext candidate before returning `{credentialRef, generation}`. Do not send `secrets` to the browser. |
| `inspect(binding, credentialRef)` | Verify the exact prepared/active reference and validate its supported payload format; return metadata **only**. A candidate is not usable. |
| `readForManagement(binding, credentialRef)` | **Backend only**, for discovery/eligibility after verifying management operation ownership. Reads the exact active or prepared reference and returns `{...metadata, state: "active"\|"prepared", secrets}`. Does not publish a candidate or grant inference admission. |
| `resolveBinding({channelId, authProfile, credentialRef})` | For **trusted server config only**: require the exact stored channel/profile/reference and a valid supported payload before returning `{channelId, principalId, profile}`. Useful on restart; not an HTTP lookup service or a substitute for draft ownership. Run `admit` independently for each request. |
| `resolveIdentity({channelId, authProfile, credentialRef})` | Backend-only metadata lookup for reauthorization/revocation. Requires the exact existing reference and stored profile/principal, but never reads or decrypts secrets and never authorizes inference. This remains available for legacy ciphertext. |
| `activate(binding, credentialRef, expectedGeneration)` | After config publication, atomically install candidate; idempotent for the current active reference. |
| `activateMany([{binding, credentialRef, generation}, ...])` | The proxy-apply stage promotes the changed references in one credential-store transaction. A conflict on any row rolls back the entire batch. Neither inference nor the background scheduler promotes candidates. |
| `admit(binding, credentialRef)` | Read authoritative shared state; return `{secrets, generation, credentialVersion, ...}` only for current active reference. Never expose this object in admin responses, logs, traces or metrics. |
| `refresh(binding, credentialRef, async (secrets, {signal}) => newSecrets, options = {})` | Coalesce concurrent local work, acquire per-channel lease, commit only under current generation/version/fence. Returns metadata **only**. Admit again for a new request. Options: `leaseMs` (default 30,000, maximum 300,000), `expectedCredentialVersion` (reject stale attempts), `rotating` (see below). |
| `revoke(binding, expectedGeneration, expectedCredentialVersion?)` | Discard current and pending secrets; preserve lifecycle tombstone. Pass the observed credential version when invalidating after a provider response; an old 401 must not invalidate a newer token. |
| `discardPrepared(binding, credentialRef, expectedGeneration)` | Reclaim **only** the exact pending reference after checking publication state. Time alone never authorizes deletion. |
| `close()` | Abort local refreshes, drain local storage operations and release sidecar writer guard. Caller owns the database pool. |

`secrets` is a bounded, nonempty plain JSON object (32 KiB maximum). On read it is a non-enumerable property of the wrapper, **not** a safe object to log separately. The caller must implement profile-specific payload and expiry validation, provider authorization and endpoint trust, request timeout/retry policy, and signals for upstream work. No OAuth, discovery, network retry or account selection takes place in this store.

## Publishing and recovery

1. Verify the provider principal and server-owned channel/draft, then prepare at the observed lifecycle `generation`. The returned random reference is not authorization. At most one candidate exists per channel: another prepare is refused, never allowed to replace a candidate that might already be referenced. A failed config CAS leaves the current active reference untouched; retry the original publication with the same candidate.
2. Before saving, validate candidate ownership, trust and discovery independently. After saving, activate the exact saved reference during apply. Activation increments lifecycle `generation` and `credentialVersion`; refresh increments only `credentialVersion`. Activation can be retried after a crash between save and apply. These are **not** multi-store transactions. Never activate an old config history reference just because it exists in history.
3. Use `admit` at **each** new inference admission, not `readForManagement`, `status`, or a cached token. Revocation commits a tombstone; subsequent reads deny the old reference. A request already admitted is not retroactively cancelled. This is local invalidation, not revocation of the application's grant at the provider.
4. For one-use or possibly rotating refresh tokens, pass **`rotating: true`**. The store durably marks the operation *before* calling the provider, so a crash, timeout, or ambiguous local write cannot cause reuse of the old refresh token. Admission/management use of the old credential is blocked while this marker is present. If not successfully cleared by the same fenced write, require fresh login or explicit revocation; don't clear it on a timer. The default `false` is for operations known not to invalidate the source credential (e.g. a documented repeatable token exchange).

On a single file writer, closing the draft leaves an authorized session available for 30 minutes after its last status read. The cleanup job takes the configuration mutation lock and checks active config, saved config, the latest file, pending-sync state, candidate reference and generation before discarding it. In database mode an idle instance cannot prove that other instances have abandoned publication, so it only drops its in-memory session. Explicitly discard unused candidates while their references are known; never delete credential rows or remove a rotation barrier to unblock publication.

## Storage and failure boundaries

- **File:** supply a dedicated private directory under an existing, trusted parent; no untrusted account may replace the path or its ancestors. World/group-accessible credential directories/data files, symlinks in the chosen path and multiply-linked data files are refused. The local SQLite sidecar stores plaintext JSON, uses an exclusive OS lock, durable rollback-journal commits and directory synchronization. Closing or process death releases the lock. `CREDENTIAL_WRITER_BUSY` is a deployment error, not permission to delete the sidecar. Do not copy individual sidecar/journal files while open. Use local POSIX storage with working locks and fsync; network/multi-writer mounts are not a supported coordination mechanism. Local disk I/O is synchronous.
- **PostgreSQL:** use the primary and a pre-existing, access-restricted schema. Bootstrap creates `copilot_credentials_v1`; provision CREATE/usage/DML privileges or pre-provision that table and appropriate privileges. Each mutation takes a short row lock and checks the caller's versions under it. The refresh callback runs **outside** the transaction. An expiring lease uses the database clock and an increasing fence; the final write checks the lease again in SQL. Other instances receive `CREDENTIAL_LEASE_BUSY`: wait within the caller's deadline or re-admit an independently verified, still-valid token. A failed lease release is reported; never override another worker's fence. Configure finite pool acquisition, connection and database statement timeouts. Never point admission at a read replica (standby reads are rejected). No fallback to a local copy during an outage.
- Protect backups with external encryption and access controls until global application-layer encryption is implemented. Secure deletion of every historical record, replica or backup is not promised. Legacy ciphertext backups remain encrypted, but this runtime cannot decrypt them; retain the original keys separately if an offline older-version recovery is needed.
- Trust the sidecar/database administrator and storage durability. Reading or editing plaintext storage can expose credentials or alter stored principals/approval keys; the runtime's ownership checks do not provide cryptographic protection against the storage administrator. Replaying an old database/backup or failing over to a stale unsynchronized primary can also replay old state. Fence former writers and invalidate/reconcile with the authoritative deployment before enabling restored channels. File and PostgreSQL state are separate, with no silent failover/migration. Loss of the store must require reauthorization, not restoration of credentials from config history.
- API errors have fixed `code` and `message` and no raw cause. Only allowlisted lifecycle codes and versions should reach existing operation logs. Never log payloads, ciphertext, key material, headers, OAuth responses, device codes, or token fingerprints. Disable SQL bind-parameter tracing for this table. Protect management endpoints and drafts separately; do not make `preparedRef` or a caller-provided `principalId` a claim mechanism.

## Offline validation

`node --test test/copilot-credentials.test.js` runs plaintext persistence without keys, legacy ciphertext retention/replacement/discard, malformed payload/unknown format rejection, private sidecar permissions, process exit, concurrency, timeout and shutdown cases. For the shared-authority and fault-injection case, supply `RUNTIME_MEDIA_TEST_DATABASE_URL` **only** for a disposable loopback PostgreSQL; the test creates/drops its own random schema. Neither path contacts an OAuth or inference service.
